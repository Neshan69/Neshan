# SEO

Search Engine Optimization reference for the Neshan Niroula portfolio. This file is the single source of truth for SEO behavior and **must be updated whenever SEO changes are made** (titles, descriptions, routes, structured data, robots/sitemap, analytics).

> Stack: React 19 + Vite SPA. Meta tags are set client-side with `react-helmet-async` (`src/components/SEO.jsx`), driven by `src/lib/seo.js`. Structured data (`@graph` JSON-LD) is emitted statically in `index.html`, generated by `src/lib/structuredData.js`.

---

## Meta title strategy

- **Single source of truth:** every route's `<title>` lives in the `ROUTES` map in `src/lib/seo.js` (`getSeoData(routeKey)`).
- **Format:** `Brand | Descriptor` for the homepage, `Page | Brand` for sub-pages.
  - Home: `Neshan Niroula | UI/UX Designer & Systems Architect`
  - Admin: `Admin Dashboard | Neshan Niroula`, `Manage Users | Neshan Niroula`, `Messages | Neshan Niroula`, `Settings | Neshan Niroula`
  - 404: `Page Not Found | Neshan Niroula`
- **Brand constant:** `SITE_NAME = "Neshan Niroula"` (kept in one place so renames touch a single line).
- **Length:** kept under ~60 characters to avoid truncation in SERPs.
- **Static fallback:** `index.html` ships the homepage `<title>` so crawlers/OG parsers that don't execute JS still get a correct title.
- **To change a title:** edit the matching entry in `ROUTES` in `src/lib/seo.js`.

## Meta description strategy

- Each route defines a `description` in `ROUTES` (homepage description ≈ 155 characters; concise, benefit-led, includes the primary keyword phrase "UI/UX Designer & Systems Architect").
- Rendered as `<meta name="description">` by `SEO.jsx`. Also present as a static fallback in `index.html`.
- Descriptions are written to entice clicks (value + intent), not stuffed with keywords.
- **To change a description:** edit `ROUTES[routeKey].description` in `src/lib/seo.js`.

## Keywords

- **No `<meta name="keywords">` tag is used** — Google ignores it, and it adds no ranking value. Keyword targeting is expressed through titles, the meta description, headings (`h1`/`h2`), and visible copy instead.
- **Primary keyword:** `UI/UX Designer & Systems Architect`
- **Secondary / supporting keywords** (used in headings and body copy):
  - `Editorial aesthetics`, `precision systems`, `high-impact digital experiences`
  - `Frontend Engineering`, `Design Systems`, `Web Security`, `Systems Architecture`
  - `Portfolio`, `Cyber-Ops Interface`, `Ether Reality OS`, `Monolith Boutique` (project names)
  - `Remote / Worldwide` (service area)
- These are mirrored in the `Person.knowsAbout` array in `src/lib/structuredData.js` so structured data and on-page targeting stay consistent.

## Structured Data

- **File:** `src/lib/structuredData.js` → `getStructuredData()` returns a schema.org `@graph`.
- **Rendered:** statically inside `index.html` as `<script type="application/ld+json">` (crawlable without JS execution).
- **Entities included:**
  - `WebSite` (publisher → Organization, author → Person)
  - `Organization` (logo = `favicon.svg` 48×46, `founder` → Person, `contactPoint` → ContactPoint)
  - `Person` (name, `jobTitle`, `knowsAbout`, `alumniOf`, `address`, `worksFor`, image)
  - `WebPage` (`isPartOf` WebSite, `primaryImageOfPage` = OG image 1200×630, `breadcrumb`)
  - `BreadcrumbList` (Home)
  - `Collection` ("Portfolio") whose `hasPart` are the three `Work` projects, each typed `["SoftwareSourceCode","CreativeWork"]`
  - `ContactPoint` (contactType `sales`, real `#contact` anchor, `areaServed`, `availableLanguage`)
- All entities are cross-linked via stable `@id` fragment references (`#website`, `#organization`, `#person`, `#webpage`, `#breadcrumb`, `#portfolio`, `#contactpoint`, `#project-*`).
- **Validation:** `node validate-sd.mjs` confirms the HTML JSON parses, that every `{ "@id" }` reference resolves, and that all required types are present.
- **Notes:** `Portfolio` uses the schema.org `Collection` type (there is no `Portfolio` type). `SoftwareSourceCode` intentionally omits `codeRepository`/`programmingLanguage` because no real repo URLs exist — fabricated values are avoided. Project data is shared from `src/data/projects.js`.

## Robots

- **File:** `public/robots.txt`
  ```
  User-agent: *
  Allow: /
  Disallow: /admin/

  Sitemap: https://neshanniroula.com/sitemap.xml
  ```
- Public content is crawlable; the admin area is disallowed (it is also `noindex`).
- Per-route `robots` meta is also emitted via Helmet (`SEO.jsx`): `index, follow` for the homepage, `noindex, nofollow` for `/admin*`, `adminUsers`, `adminMessages`, `adminSettings`, and the 404 page (values in `src/lib/seo.js`).

## Sitemap

- **File:** `public/sitemap.xml`
- Lists only public, indexable URLs. Currently the homepage (`priority 1.0`, `changefreq monthly`).
- Admin URLs are intentionally **omitted** (they are disallowed in `robots.txt` and `noindex`), keeping the sitemap consistent with crawl directives.
- `index.html` links the sitemap via `<link rel="sitemap" href="/sitemap.xml">`.
- **When adding public routes:** add a `<url>` entry to `public/sitemap.xml` with `lastmod`, `changefreq`, and `priority`. Update `ROUTES` in `src/lib/seo.js` in parallel.

## Canonical URLs

- Every route emits an absolute `<link rel="canonical">` (e.g. `https://neshanniroula.com/`, `https://neshanniroula.com/admin`).
- Defined per route in `src/lib/seo.js` (`canonical`), rendered by `SEO.jsx`. The homepage canonical is also statically present in `index.html`.
- **Why absolute:** prevents duplicate-content issues from `www`/non-`www`, HTTP/HTTPS, and query-string variants. Ensure the production host serves the SPA at the canonical `SITE_URL` and redirects variants (e.g. `www.`, `http://`) to it.
- The 404 route canonical points to `/` but is `noindex`, so it is never indexed as a duplicate.

## Open Graph

- Rendered by `SEO.jsx` for every route: `og:type`, `og:site_name`, `og:locale` (`en_US`), `og:title`, `og:description`, `og:url`, `og:image`, plus `og:image:width` (1200), `og:image:height` (630), and `og:image:alt`.
- Shared image: `https://neshanniroula.com/og-image.svg` (static 1200×630 social card in `public/`).
- The homepage also ships a static OG block in `index.html` for non-JS parsers.
- **Tip:** if richer per-page previews are wanted later, generate a PNG/JPEG `og-image` per route (SVG is not rendered by all social scrapers) and set `og:image` per route in `src/lib/seo.js`.

## Twitter Cards

- Rendered by `SEO.jsx`: `twitter:card` = `summary_large_image`, `twitter:site` = `@neshanniroula`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`.
- Static fallback block also present in `index.html`.
- Update `TWITTER_HANDLE` in `src/lib/seo.js` if the handle changes.

## Lighthouse scores

- **Target:** SEO **100**, Accessibility **≥ 95**, Performance green (LCP/CLS/INP).
- **What supports these targets:**
  - SEO 100: valid `<title>` + meta description on every route, canonical, OG/Twitter, crawlable links, `robots.txt`, `sitemap.xml`, valid JSON-LD, `lang="en"`, viewport that allows zoom, descriptive `alt` text, no `noindex` on public pages.
  - Accessibility ≥ 95: heading hierarchy, `aria-label`s on icon buttons, form labels, `alt` text, skip link, visible `:focus-visible` outline, WCAG-AA contrast (opacity text bumped to `/80`).
  - Performance: fonts loaded non-render-blocking (`media="print" onload` swap), Supabase/vendor/framer split into cacheable chunks, decorative images `fetchpriority="low"`, reduced-motion guards.
- **How to verify:** `npm run build && npm run preview`, then run Lighthouse (Chrome DevTools → Lighthouse, or CI) against the preview URL. Re-run `node validate-sd.mjs` whenever structured data changes.

## Search Console setup

1. Go to <https://search.google.com/search-console/> and **Add Property** → choose **URL-prefix** `https://neshanniroula.com/` (or Domain verification if you control DNS).
2. **Verify ownership** — use the HTML tag method: add the provided `<meta name="google-site-verification" content="...">` to `<head>` in `index.html` (place it right after the `<meta name="viewport">` line), or verify via DNS TXT record.
3. **Submit the sitemap:** in Search Console → **Sitemaps** → enter `sitemap.xml` (resolves to `https://neshanniroula.com/sitemap.xml`). It is already referenced in `robots.txt`.
4. **Request indexing** of `https://neshanniroula.com/` via **URL Inspection**.
5. **Monitor:** Coverage, Mobile Usability, Core Web Vitals, and the rich-result status of the JSON-LD (test with the Rich Results Test / Schema Markup Validator).
6. Keep `robots.txt` allowing `/` and `sitemap.xml` reachable.

## Google Analytics setup

> Status: **not yet installed.** Add it to start measuring organic traffic.

1. Create a GA4 property and copy the Measurement ID (`G-XXXXXXX`).
2. In `index.html`, add the gtag.js snippet inside `<head>` (after the font `preconnect` links, before the JSON-LD block):
   ```html
   <!-- Google Analytics (GA4) -->
   <script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXX"></script>
   <script>
     window.dataLayer = window.dataLayer || [];
     function gtag(){dataLayer.push(arguments);}
     gtag('js', new Date());
     gtag('config', 'G-XXXXXXX');
   </script>
   ```
3. Replace `G-XXXXXXX` with the real ID. Keep the snippet small and async so it does not hurt LCP.
4. (Optional, recommended) Respect privacy/consent: gate the snippet behind a consent banner and only load it after consent.
5. Link the GA4 property to the Search Console property (Admin → Product Links) for Search Queries reporting.
